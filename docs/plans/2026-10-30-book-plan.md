# 本（Deep dive into mruby）の図に使うための改修計画

2026-10-30。fork（kishima/bitgram）で、本の図版を作るのに要る分だけを足す。本家への PR は本が出た後に考える（著者判断 2026-10-30）。
本家と衝突を減らすため、既存の挙動は既定のまま変えず、足すものは設定かオプションで有効にする。

## 前提（本の側の約束）

- 図は PDF で Re:VIEW に読ませる（`images/<章名>/<図名>.pdf`）。元データは `images/src/<章名>/` に置き git で管理する。
- 文字は **M PLUS 1p**（`~/.fonts/MPLUS1p-{Regular,Bold}.ttf`、TrueType）。PDF にサブセットで埋め込まれ、Type3 にならないこと（入稿の確認 `tools/check_print_pdf.py`）。
- 既存の draw.io の図は、線 `#000000`、塗り白、文字 10〜11pt。並べて浮かない見た目にする。
- 根拠のない数を書かない（`/home/kishima/book/CLAUDE.md`）。寸法などの既定値は設定で変えられるようにし、出どころを 1 行残す。

## 試し描きで分かったこと（2026-10-30、upstream eeb5ae3）

スクラッチパッドで ENTER の欄割り、オブジェクトヘッダ、RITE バイナリヘッダを描いた。

1. `svg.font_family: "M PLUS 1p"` が CSS に `font-family: M PLUS 1p;` と引用なしで出る。`1p` が数字で始まる識別子なので CSS として無効になり、serif に落ちる。`"'M PLUS 1p'"` と書けば効く。
2. Chromium（`~/.cache/ms-playwright/chromium-1243`）の `--print-to-pdf` で、SVG を包んだ HTML から PDF にできた。M PLUS 1p は `/FontFile2`（TrueType サブセット）で埋め込まれた。ただし高さ 149.4px の図で **2 ページ** になった（端数の繰り上がり）。
3. 1bit の欄（`frozen`）は名前が入らず、脚注 `*1` が縦に 2 行で出て読みにくい。
4. `lsb0` でも欄は書いた順に左から並ぶ。C のビットフィールドは宣言順が LSB からなので、逆順に書き直す必要がある。
5. ENTER の図（`images/opcodes/enter_aspec`）にある「例のビット列」「欄の値」「5bit」の行は描けない。Word Boxing（`contents/vm.re:202`）のように行ごとに種別名を左に付ける形も描けない（左の欄はバイトオフセットだけ）。

## 段階

### B1. フォント名の引用と、本の既定設定

- 到達点: `font_family` に空白や数字始まりの語を含む名前を書いても、CSS で正しく引用される。既に引用されているものは二重にしない。
- 本の既定（フォント、文字の大きさ、線と塗りの色）を、図ごとに繰り返さずに済む形にする。案: `--config PATH`（または定義の `extends: PATH`）で共通の YAML を読み、定義側の値で上書きする。どちらにするかは実装で既存の `Config` の合成を読んで決め、報告する。
- 確認: rspec に引用のテスト。試し描きの `header.yml` を引用なしで描いて M PLUS 1p になること。

### B2. PDF 出力

- 到達点: `bitgram render x.yml -o x.pdf`（`-f pdf`）で、図の寸法ちょうどの **1 ページ** の PDF ができる。
- 方式: ヘッドレス Chromium の `--print-to-pdf`。`@page` の寸法は SVG の幅・高さを切り上げ、`overflow: hidden` で 2 ページ目を出さない。Chromium の場所は設定（環境変数か `raster` と並ぶ `pdf.chrome`）で指定でき、既定は PATH と `~/.cache/ms-playwright/*/chrome-linux64/chrome` を探す。タイムアウトは既存の `raster.timeout` に揃える。
- 確認: 出力が 1 ページで、MediaBox が SVG の寸法（px × 0.75 pt）に一致すること、フォントが `/FontFile2` であることを pypdf で確かめる rspec（Chromium が無ければ skip）。

### B3. 欄を LSB から書く

- 到達点: `layout.field_order: lsb_first`（既定 `msb_first` = 今の挙動）で、欄を C の宣言順に書ける。
- 確認: オブジェクトヘッダを `tt, gc_color, frozen, flags` の順に書き、`tt` が bit 7〜0（右端）に出ること。

### B4. 細い欄の名前

- 到達点: 1〜2bit の欄の名前を読める形で出す。案は (a) 欄の上か下に名前を出して引き出し線でつなぐ、(b) 縦書き、(c) 今の脚注を 1 行で出す。既存の `fit_order` の仕組みに戦略として足す。どれを既定にするかは、描いた PNG を著者に見せて決める（実装担当は 3 案の PNG を報告に付ける）。

### B5. 欄の下の注記行と、行の見出し

- 到達点:
  - 欄ごとの注記行: 定義のトップレベルに `annotations:`（行の名前と、欄 id → 文字列の対応）を置き、欄の下に行を足す。ENTER の「例のビット列」「欄の値」「ダンプの順」、各欄の「5bit」がこれで描ける。行の名前は左に出す。
  - 行の見出し: 論理行ごとに左の欄に文字列を出せる（`layout.row_labels` か、欄に `row_label`）。オフセットの代わりに使う。Word Boxing の nil／false／…／object の各行がこれで描ける。
- 確認: `enter_aspec` と同じ内容を YAML で描き、既存の PNG（`book_mruby3/images/png/opcodes/enter_aspec.png`）と並べた PNG を報告に付ける。Word Boxing も同様。

### B6. 本の側の組み込み（本のリポジトリで行う。fork の段階ではない）

- `book_mruby3/tools/bitgram2pdf.sh`（`drawio2pdf.sh` と同じ形。`images/src/<章名>/*.bitgram.yml` → `images/<章名>/*.pdf` → PNG）。
- Gemfile か `tools/` から fork のコミットを固定して参照する。
- 最初の 1 枚で `tools/build_pdf.sh --print` の `check_print_pdf.py` を通す。
