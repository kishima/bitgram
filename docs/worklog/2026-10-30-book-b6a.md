## 1. 欄の名前を太字にする（`svg.field_font_weight`）

既存の draw.io の図（`book_mruby3/images/src/opcodes/enter_aspec.drawio`）は、欄の名前だけを `<b>` で太字にし、ビット番号や「1bit」「欄の値」などは普通の太さで書いている。これに合わせるため、`svg.field_font_weight`（`normal` / `bold`、既定 `normal`）を足した。

太字にするのは欄の名前だけで、場所は 3 つある。枠の中の名前（`Cells#draw_label` の 1 つ目、class `bg-label`）、`rotate` で回した名前、`leader` で行の下に出した名前（`Svg#draw_leaders`）。値（`bg-value`、`= 3` の行）と注記行（B5 の `annotations`）は太字にしない。

最初は「class が `bg-label` の text を太字にする」と考えたが、B5 の注記行も `draw_label` を通るので class が `bg-label` になっている（`spec/bitgram/renderers/annotations_spec.rb:37` がこの class で注記の文字を拾っている）。class を変えると B5 の出力が変わるので、`draw_label` に `names:`（既定 `true`）を足し、注記行（`Annotations#draw_annotation_box`）からは `names: false` で呼ぶことにした。

書き方は SVG の表示属性 `font-weight="bold"` を各 `<text>` に付ける形にした（`Svg#text_attributes` の `bold:`）。`ligatures` は CSS の規則と inline の `style` の 2 通りで書いたが、`font-weight` は表示属性なので 1 か所で `inline_styles` の有無に関わらず効く。CSS の規則には `font-weight` を書いていないので、属性と衝突しない。既定（未指定か `normal`）では何も出さないので、既存の出力は変わらない。既定値は B3 以来の理由（`Config::DEFAULTS` の `svg` に足すと題の無い図の id のハッシュが変わる）で DEFAULTS に書かず、`"bold"` と等しいかだけを見ている。

rubocop が `draw_rotated` と `draw_label_lines` の引数の数（6）と `draw_label` の循環的複雑度（13）を指摘したので、名前か値かと太字の判断を `label_style` にまとめ、2 つの関数には出来上がった属性の Hash を渡すようにした。

### PDF で Bold が埋め込まれるか

`impl-b6/bold_probe.yml`（B4 の `book.yml` に `field_font_weight: bold` と `fit_order: [single, shrink, leader, truncate]` を足したもの）で、B4 のオブジェクトヘッダ（`impl-b4b5/header_leader.yml`）を PDF にし、B1 の `pdfcheck.py` でフォントを見た。

```
$ bundle exec exe/bitgram render impl-b4b5/header_leader.yml --config impl-b6/bold_probe.yml -o impl-b6/bold_probe.pdf
$ python3 impl-b1b3/pdfcheck.py impl-b6/bold_probe.pdf
pages 1
page 0 MediaBox [0.0, 0.0, 504.0, 108.0]
  /F4 /Type0 /CIDFontType2 /AAAAAA+MPLUS1p-Regular ['/FontFile2']
  /F6 /Type0 /CIDFontType2 /BAAAAA+MPLUS1p-Bold ['/FontFile2']
```

Chromium は `~/.fonts/MPLUS1p-Bold.ttf` を選び、Bold の TrueType サブセット（`/FontFile2`）として埋め込んだ。擬似ボールド（Regular を太らせる）なら Bold のフォントは現れず、Type3 にもなっていない。

文字幅の見積もり（`char_width_ratio` 0.6）は太さを見ていない。Bold は Regular より字幅が広い可能性があるが、測っていない。本の図で名前が枠からはみ出していないかは、PNG を目で見て確かめる（B6 の記録）。

## 2. `bit_numbers: false` でも複数ビットの欄に残る目盛り

`Decorations#draw_ticks`（`lib/bitgram/renderers/svg/decorations.rb:92-106`）は、各行の上辺に、ビットの境目ごとに長さ 4px の縦線（`bg-tick`）を描く。欄の境目では枠の縦線に重なって見えないので、見えるのは複数ビットの欄の中だけになる。Word Boxing では「…」（2bit）の中の 1 本がこれ。`bit_numbers` とは独立で、`svg.ticks` だけで切り替わる（`Svg#draw_rows` の `if @options["ticks"]`）。

```
ticks true: 72      # Word Boxing（10bit × 8 行、境目 9 本 × 8 行）
ticks false: 0
```

`svg.ticks: false` で全部消える。欄ごとに消す設定は無いが、目盛りは欄の境目以外では「この欄は何ビットか」を示すためのもので、ビット番号を出さない図では要らない。欄ごとの設定は足さなかった。本の側で `ticks: false` を図ごとに書くか共通にするかは B6 で扱う。

## 3. 題が図の幅より長いとはみ出す

`Svg::Geometry#initialize` の `@width` は余白、左の欄、ビットの幅だけで決まり、題の幅を見ない（本家の挙動）。本では題を図に入れずキャプションに書く見込みなので、`show_title: false` で困らないかを確かめた。

```
width="192" height="92"     # 題なし
width="192" height="92"     # 長い日本語の題 + show_title: false
bg-title の text: 0
<title id="bitgram-4ed16e68-title">とても長い題…   # アクセシビリティ用の <title> には残る
```

`show_title: false` では題の高さが 0 になり（`Geometry#measure_header`）、図の寸法は題の無い図と同じで、はみ出しは起きない。題は SVG の `<title>` 要素にだけ残る（画面には出ない）。

直さなかった。直すなら `Geometry` で題の幅（`@measurer.width(title, size: font_size * 1.2)` + 余白）と今の幅の大きいほうを図の幅にし、表を中央に寄せるために `@x` に差の半分を足す。10 行ほどと rspec 1 例。ただし既定で入れると、長い題を持つ既存の図の出力が変わる（本家の挙動の変更）。設定で有効にする形にするかを含めて、著者の判断を待つ。
