## なぜ要るか

著者の方針（2026-10-30）は「ビット番号と目盛りは、それで欄の大きさが明確になるなら出す」。本の Word Boxing の図（`book_mruby3/images/src/vm/word_boxing_layout.bitgram.yml`）は、64bit のうち上位 56bit を「…」の 2bit 幅の欄 1 つで表し、下位 8bit を 1bit ずつ描く。`layout.bit_numbers` は図全体でしか切り替えられないので、番号を出すと「…」の上に 9、8 が出て誤りになり、B6 では図全体の番号を消していた。下位 8bit の上には 7〜0 を出したい。

## 決めたこと

**欄に `bit_numbers`（真偽、既定 `true`）を足した。** `false` の欄では、その欄の列の上のビット番号を出さない。

ビット番号は図に 1 回だけ、最初の行の上に描かれる（`Decorations#draw_header` → `draw_numbers`、`lib/bitgram/renderers/svg/decorations.rb`）。番号は列（`col`）ごとで、行ごとではない。そこで「その欄の上の番号」を、**最初の行で、その列に描かれている欄が `bit_numbers: false` なら、その列の番号を出さない**、と決めた。2 行目以降にある欄の `bit_numbers: false` は番号に効かない（その列の上にある番号は、最初の行の別の欄のものだから）。列の集合は `Layout::Result#unnumbered_columns` で作り、SVG と ASCII の両方から使う。`Cell#col` は描く位置（左から）なので、`field_order: lsb_first` でもそのまま使える。番号の行の高さは変えない（行ごと消すのは今までどおり `layout.bit_numbers: false`）。

**目盛りも、その欄の中では消すことにした。** `Decorations#draw_ticks` は、各行の上辺に、列の境目ごとに長さ 4px の縦線を描く。欄の境目では枠の縦線に重なって見えないので、見えるのは複数ビットの欄の中だけで、意味は「この欄は何ビットか」（B6a の記録の 2）。ビット番号と目盛りはどちらも「1 列 = 1bit」と言っている。`bit_numbers: false` を付ける欄は、列の数が実際のビット数でない欄（「…」）なので、番号だけ消して目盛りを残すと、目盛りが「2bit」と言い続けて誤りが残る。欄ごとに `ticks` を別に足す案も考えたが、番号を消して目盛りを残したい欄の例が思い当たらず、設定を 2 つに分けると書く側が両方を揃える必要が出るので、1 つにまとめた。目盛りは行ごとに描かれるので、番号と違い、その欄がある全部の行で消える（`Decorations#inside_unnumbered_field?`。境目が欄の内側、つまり欄が境目の両側にかかるときだけ消す）。merge した block の左右の横向きの目盛りは欄と関係がないので変えていない。

ASCII にも同じ規則で入れた（`Ascii#header`）。ASCII には目盛りが無い。

## 落とし穴: `Model::Field` に足すと題の無い図の id が変わる

B3〜B5 の記録のとおり、題の無い図では `Svg#default_prefix` が `fields.map(&:to_h)` を含む設定全体のハッシュを id にする。`Model::Field` に `bit_numbers` を足すと、使っていない定義でも `to_h` に `bit_numbers: true` が入り、id が変わる。B5 の `annotations` と同じ扱いで、`Svg#field_digest` で既定値（`true`）のときはハッシュから外した。`false` を書いた図の id は変わる（中身が違う図なので、それでよい）。rspec に、B3 の id `bitgram-408ce7c0-diagram` が `bit_numbers` を書かない定義でも `true` を明記した定義でも変わらないこと、`false` では変わることを入れた。

B5 で行の見出しを欄に持たせなかった理由の 1 つがこの落とし穴だったが、今回は欄の性質（この欄の列はビットに対応しない）なので欄に持たせるのが自然で、`layout` に列の番号の一覧を書く形（`layout.hidden_bit_numbers: [8, 9]` のような）は、欄を足したり幅を変えたりするたびに数を直す必要があるので採らなかった。
